Сценарий закупщика

  1. Поиск: категория, город, сумма/объём заказа → ранжированная выдача со сводкой по рынку.
  2. Настройка приоритетов: веса критериев ползунками — порядок пересчитывается сразу.
  3. Карточка: контакты, условия, документы, реестр, откуда взято каждое поле, флаги рисков.
  4. Добор данных одной кнопкой: прочитать сайт (LLM), проверить юрлицо в реестре, найти ИНН.
  5. Сравнение 2–4 поставщиков бок о бок, лучшее значение подсвечено.
  6. Действие: письмо-запрос КП, статус в воронке, заметки команды, экспорт CSV.
  7. Нет нужного в базе → живой поиск по Яндекс.Картам → «В базу» → автообогащение.
  8. Или всё сразу: AI-ассистент — задача текстом, агент сам вызывает инструменты.

Как считается балл

Балл = Σ(весi × оценкаi) / Σ весов × 100. Оценка каждого критерия 0…1 и всегда с текстовым объяснением.

КритерийВес по умолчаниюЛогика
Соответствие{{ weights.relevance }}профильная категория = 1, дистрибьютор широкого профиля = 0.6; бонус за совпадения ключевых слов в ассортименте
География{{ weights.geo }}в городе = 1, доставляет в город = 0.85, «вся Россия/Казахстан» = 0.6, иначе 0.3; другая страна 0.05
Надёжность{{ weights.reliability }}по реестру: не действует = 0; возраст ≥10 лет = 1 … <1 года = 0.15. Нет реестра: ИНН на сайте = 0.5, нет ИНН = 0.35
Документы{{ weights.documents }}декларации ЕАЭС +0.4, ХАССП/ISO 22000 +0.3, «Меркурий» +0.3 (для рыбы, мяса, молочки), халал +0.1
Коммерция{{ weights.commercial }}мин. заказ ≤ вашего = 0.85, больше — пропорционально; бесплатная доставка, отсрочка, цены — бонусы
Полнота данных{{ weights.completeness }}доля заполненных ключевых полей — чем меньше «белых пятен», тем меньше риск сюрпризов

Флаги риска (не влияют на балл, но видны сразу): компания не действует или моложе года, нет ИНН, нет прямых контактов, не подтверждён «Меркурий» для животной продукции, мин. заказ выше вашего, данные старше 180 дней.

Архитектура

Браузер (Jinja + HTMX, дизайн-токены в theme.css)
   │
FastAPI ── scoring.py   прозрачный скоринг + флаги + сводка по выдаче
   │   ├── agent.py     цикл «мысль → инструмент → результат», JSON-протокол, ≤6 шагов; без LLM — правила
   │   ├── service.py   обогащение с записью происхождения каждого поля (не затирает ручные правки)
   │   └── sources/     site.py (сайт + regex + LLM, защита от SSRF) · dadata.py (РФ/РК) · yandex.py
   │
SQLite: suppliers (JSON-поля: категории, регионы, документы, provenance, ответ реестра) · notes · statuses
LLM: OpenRouter, бесплатные модели с автоматическим перебором при лимитах

Ограничения прототипа и что дальше

  • Цены публикуют редко — поле заполняется из КП и заметок; дальше — разбор присланных прайсов (PDF/Excel) через LLM и история цен.
  • Росаккредитация и «Меркурий» без публичного API — сейчас ссылки и ручная отметка; дальше — интеграция через официальный доступ.
  • Бесплатные LLM ограничены по запросам; прод — платная модель или своя, кэш извлечений уже есть.
  • Вход по имени без пароля — для демо; прод — SSO компании и роли.
  • Следующие шаги: рассылка запросов КП и разбор ответов агентом, рейтинг поставщиков по факту поставок (качество, сроки), интеграция с учётной системой сети.
